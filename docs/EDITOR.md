# Miracle 에디터

> 상태: 초안 v0.2. 언어 명세는 [`SPEC.md`](../SPEC.md).
> **[확정]** 선우가 정한 방향. **[제안]** 검토 중인 안. **[열림]** 아직 답이 없는 질문.
> 작은 프로토타입: [`editor/`](../editor)

---

## 0. 한 문단 요약

원본은 텍스트이고, 에디터는 그 텍스트를 **투영**한다. 결과, 모양, 역참조는 해당 줄 옆에 코드를 가리지 않고 얹힌다. 가정, 묶기, 풀기, 불러오기는 다른 파일로 가지 않고 **그 자리**에서 끝난다.

## 0.1 살아 있는 개요 [확정]

글을 쓰는 자리에 앱이 이미 돌고 있다. 따로 여는 창은 없다.

- **블록이 곧 미리보기.** `model` 아래엔 지금 데이터 표, `interface` · `component` 아래엔 실제 화면, `system` 머리엔 `▶ 사건` 단추가 붙는다. 미리보기에서 버튼을 누르면 진짜 사건이 흐르고, 모든 블록이 **같은 세계 하나**를 보고 같이 바뀐다. 실패하면 통째로 되돌아가고 실패 사건까지 흐른다.
- **정보는 커서 줄에만.** 커서 아래 이름의 종류 · 타입 · 지금 값 · 쓰는/읽는 system 이 그 줄 끝에 붙는다(렌즈). 코드를 가리는 팝업은 없다. 마우스를 올리면 정의 블록을 작게 그대로 보여 주고, 그 줄을 누르면 간다.
- **할 일은 늘 보인다.** 맨 위 띠에 "지금 자리에서 할 수 있는 것"이 말로 떠 있고, `/` 를 치면 같은 목록이 커서 자리에 뜬다. 고르면 칸이 비어 있는 틀이 들어가고 `Tab` 으로 채운다. 줄 끝에는 아직 안 채운 칸이 흐리게 보인다(`set ▏ 대상 = 값`). 문법을 몰라도 따라 치다 보면 배운다.
- **블록끼리 무엇을 쓰는지 보인다.** 커서가 선 블록 머리에 `→ 쓰는 블록` `← 이 블록을 쓰는 블록` 칩, 왼쪽 여백에 참조 선. 이름 위면 정의 ↔ 쓰인 곳 선.
- **손은 내용만.** 들여쓰기, 칸 맞춤, 괄호 닫기는 에디터가 한다. `↵` 는 블록 머리면 안으로, 빈 줄이면 밖으로(아웃라이너). 숫자는 좌우로 끌어서, 타입은 렌즈의 후보를 눌러서 바꾼다.

## 1. 하지 않는 것 [확정]

- 맨 textarea 위에 밑줄 긋고 드롭다운 띄우고 팝업으로 코드를 가리는 방식
- 값이 궁금할 때 테스트 파일을 따로 열어 보러 가는 흐름
- 함수를 다른 파일에 `export` 하고, 옮기고, 호출부를 다시 쓰는 흐름

## 2. 그 자리의 가정과 결과 [확정]

원본에는 가정(`?`)과 기대(`!`)만 저장된다. 에디터는 그 값이 흐르는 모든 줄 옆에 결과(`→`)를 그린다.

```
model Cart  single
  lines  List<Line>   ? [Line product=펜 qty=3]
  total = sum(.lines.amount)   ! 3000                 → 3000 ✓

system Checkout  on Shop.checkout   ?
  for line in Cart.lines                              line = 펜×3
    when line.product.stock < line.qty                2 < 3 → 참
      fail OutOfStock  product=line.product           → fail OutOfStock 펜
```

- 가정 칩 `? …` 은 그 자리에서 고친다. 고치는 즉시 아래로 흐르는 결과가 다시 그려진다. [제안]
- 아무 값 위에서 `?` 를 치면 그 자리에 가정이 생긴다. [제안]
- 결과 위에서 `⌘↵` 를 치면 지금 결과가 `! 값` 으로 고정된다. [제안]
- `? A | B` 대안은 `⌥?` 로 토글한다. [제안]
- 결과는 오른쪽 여백에만 그리고, 코드 줄을 밀거나 가리지 않는다. 여백이 좁으면 줄 끝 점(`●`)으로 접는다. [제안]
- 위쪽 띠에서 `sample` 을 고르면 그 시나리오가 인라인 가정을 덮어쓴다. [제안]

## 3. 그 자리에서 묶기와 풀기 [확정]

After Effects 에서 레이어를 골라 Pre-compose 하듯, 줄을 골라 그 자리에서 묶는다. 결과는 언제나 `component` 하나다.

```
선택한 줄                                  묶은 결과

  for line in Cart.lines                     for line in Cart.lines
┃   when line.product.stock < line.qty         RequireStock  of=line
┃     fail OutOfStock  product=line.product
                                             component RequireStock  of=Line
                                               when .product.stock < .qty
                                                 fail OutOfStock  product=.product
```

- **입력은 추론된다.** 고른 줄이 바깥에서 읽는 이름이 하나면 `of=`, 여럿이면 이름 붙은 속성이 된다. [제안]
- 이름만 입력하면 끝난다. 비워두면 모양에서 이름을 제안한다. [제안]
- `↵` 로 사용처에서 **그 자리에서 펼쳐** 안을 고친다. 탭이나 파일을 바꾸지 않는다. [제안]
- **풀기**는 묶기의 정확한 역연산이다. 사용처가 여럿이면 이 자리만 풀지 전부 풀지 묻는다. [제안]
- 정의는 같은 파일 아래에 생기고, "모듈로 옮기기" 한 번으로 이사한다. `use` 는 에디터가 고친다. [제안]

---

## 4. 위에서 아래로, 아래에서 위로 [확정]

**위에서 아래로.** 없는 이름을 그냥 쓴다. 구멍(◌)으로 남고, 실행은 멈추지 않는다. `⏎` 하면 쓰인 자리에서 필요한 칸까지 추론해 선언이 생긴다.

```
list thread  of=Message                       ◌ Message 가 아직 없어요   만들기 ⏎
```

**아래에서 위로.** 펼쳐서 다 쓰고, 쌓이면 묶는다 (§3).

## 5. 불러오기와 연결하기 [제안]

- 다른 모듈의 component 이름을 치기 시작하면 고스트 텍스트로 나온다. `Tab` 으로 받으면 `use` 가 붙는다.
- 그 자리에 올 수 있는 것만 나온다. 맞지 않는 건 아예 안 나온다.
- `button send` 줄에서 `→` 를 치면 그 사건에 붙을 system 을 고르거나 만든다. 원본에는 system 쪽 `on Chat.send` 만 저장되고, 버튼 쪽 `→ Send` 는 투영이다.

---

## 6. 투영 [제안]

저장은 한 번, 표시는 필요한 모든 자리에. 회색이고 편집할 수 없다.

```
button send  "보내기"                     → Send
input draft  placeholder="메시지"          in Text · Send 가 읽고 지움
system Send  on Chat.send                  reads Chat.draft · Session.user · Clock.now
                                           writes + Message  ~ Chat.draft
```

## 7. 키보드 [제안]

```
↵            형제 줄
Tab / ⇧Tab   안으로 / 밖으로
⌥↑ / ⌥↓      줄을 안에 든 것까지 통째로 이동
⌥→ / ⌥←      선택을 의미 단위로 넓히기 / 좁히기 (값 → 줄 → 블록 → 선언)
⌘G / ⌘⇧G     묶기 / 풀기
?            가정 꽂기
⌘↵           지금 결과를 ! 로 고정
.            현재 주어의 칸 고스트 완성
```

- 지우기·복사·붙여넣기도 의미 단위다. 붙여넣으면 들여쓰기가 그 자리에 맞춰진다.
- 한글 조합 중에는 고스트 완성과 단축키를 멈춘다. 초기부터 테스트 항목이다.

## 8. 색 [제안]

색은 문법이 아니라 **역할**을 칠한다. 왼쪽 끝 단어만 봐도 무슨 줄인지 보이게.

```
선언 (model interface system component app)   굵게, 가장 진하게
interface 종류 (screen button list …)          파랑
system 문장 (when for set create …)            주황
선언 이름 · 포트 이름                            흰색 굵게 / 연하게
경로 (.author.name, Cart.lines)                 초록
문자열 · 숫자                                    노랑 · 보라
가정 ?                                          청록, 칩
기대 !                                          맞으면 초록, 틀리면 빨강
결과 →                                          회색, 투영
구멍 ◌                                          점선 밑줄
```

## 9. 그래프 [제안]

- 세 칸 고정: 왼쪽 interface, 가운데 system, 오른쪽 model. 흐름은 왼쪽에서 오른쪽, 원인에서 결과로.
- 선 세 종류: 트리거 실선, 읽기 점선, 쓰기 굵은 선.
- 자동 배치 없음. 늘 같은 자리, 선언 순서대로. 공간으로 기억하게.
- 초점 모드: 커서가 있는 줄과 바로 이웃만 밝힌다. 텍스트와 그래프의 커서는 하나다.
- 그래프에서 직접 고치기는 [열림].

---

## 10. 접근성 [제안]

DOM 기반으로 그려 스크린리더와 키보드 탐색을 지킨다. 투영과 칩도 읽을 수 있는 텍스트다. 색만으로 의미를 전하지 않고 기호를 함께 쓴다.

---

- 그래프에서 직접 고치기
- 협업할 때 꽂힌 sample 을 사람마다 다르게 둘지
